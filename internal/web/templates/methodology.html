A trade, step by step

Every trade goes through the same four steps.

  1. Pick a real trade

    Chain, pair and size follow real aggregator volume. The amount varies by up to 25%.

  2. Ask everyone at once

    Same moment, same request, same slippage, no fee, a fresh wallet. 5 seconds to answer.

  3. Execute it at once

    Each transaction runs in a simulation of the next block, with real balances and gas.

  4. Execute it 30 s later

    Again 30 seconds later: about when a user would have signed it.

What is measured

The four columns of the leaderboard. The ? of each column there gives its exact definition.

Best rate

How often it gave the user the most, after gas. Ties split the win.

Quote accuracy

How far the output 30 s later fell short of the quote, in bp (0.01%). 0 is best.

Revert rate

How many returned transactions failed when executed.

Median latency

Time until the full answer. A timeout counts as 5,000 ms.

Fair to every aggregator

The exact request of each one is in its open-source adapter.

  • Same moment, same request

    All requests are released together.

  • Every chain counts

    Everyone is asked everywhere; no route loses the trade.

  • No fees asked for

    Each API runs with its defaults.

  • Each at its best

    Asked with the key or integrator id that gets its best offer.

  • Our failures are ours

    If our infrastructure fails, the trade is dropped.

Known limits

  • Each transaction runs first in its block; other transactions ahead of it cannot be simulated. The run 30 s later is the backstop.
  • On rollups, the fee for posting data to Ethereum is not counted; it is far below 1 bp.
  • During the simulation the wallet is a contract, as many wallets are today (EIP-7702).
