How the ranking is made

Every aggregator is measured the same way, on the trades users really make. This is the short version; the full rules give every formula. Methodology version {{.Version}}.

One trade, step by step

  1. A real trade

    Chain, pair and size are drawn in proportion to real aggregator volume, read from public on-chain swaps. The amount varies by up to 25%, so no answer can be prepared in advance.

  2. The same request for all

    Every aggregator is asked at the same moment, with the same slippage (0.5%, 0.1% between stablecoins), no integrator fee and a fresh wallet. Each has 5 seconds to answer.

  3. Executed at once

    Each returned transaction is simulated as the first in the next block, where it would land if sent the moment it was quoted, with real balances, approval, gas price and gas limit. What counts is how much the wallet received.

  4. Executed 30 s later

    Each transaction that succeeded is simulated again 30 seconds later, about when a user would have signed it in their wallet.

What the leaderboard measures

Best rate % of trades

How often it gave the user the most: the output when executed at once, minus the gas the transaction costs. A trade counts once at least two aggregators delivered; an aggregator that failed in it loses it. Exact ties split the win.

Quote accuracy bp

How far the output 30 seconds later fell below the quote, on average (1 bp = 0.01%). Receiving more than quoted counts as 0, so surplus on one trade cannot hide an over-promise on another.

Revert rate % of transactions

How many returned transactions failed, at once or 30 seconds later. Errors, timeouts and missing routes are not reverts: they lose the trade under best rate.

Latency ms

Median time from sending the request to having the full answer. A timeout counts as 5,000 ms; opening the connection is not counted.

Fair to every aggregator

  • Same moment, same request. Requests are released together; the exact request of each aggregator is in its open-source adapter.
  • Every chain counts. Every aggregator is asked on every chain; on a chain it does not serve, it loses the trade.
  • No fees asked for. Each API runs with its defaults. A fee an API charges by default is what its users pay, so it is part of the result.
  • Each at its best. Aggregators serve a request by who sends it: an API key, an integrator id. Each one is asked the way that gets its best offer, so the ranking compares the best every aggregator can deliver.
  • Our failures are ours. If the benchmark's own infrastructure fails, the trade is dropped and never counted against anyone.

Known limits

  • Each transaction is simulated as the first in its block; what others ahead of it would do cannot be. The run 30 seconds later is the backstop.
  • On rollups, the fee for posting data to Ethereum is not counted. Since 2024 it is far below 1 bp.
  • During the simulation the wallet is a contract, as many wallets are today (EIP-7702).
